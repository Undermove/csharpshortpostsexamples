# Сводный анализ эксперимента

Скилл: `microbenchmarking` из [`dotnet/skills`](https://github.com/dotnet/skills/tree/main/plugins/dotnet-diag/skills/microbenchmarking)  
Задача: написать BenchmarkDotNet-проект для `SimpleKeywordEmbeddingGenerator`

## Итоги

| Метрика | Без скилла | Со скиллом |
|---|---|---|
| Чеклист (10 пунктов) | **9/10** | **9/10** |
| Tokens: Messages | **14.6k** | **6.8k** |
| Tokens: System/Tools | 20.9k | 20.9k |
| Tokens: всего | 36k (22%) | 28k (17%) |
| BDN версия в csproj | `0.14.0` ❌ | `0.14.0` ❌ |
| Структура проекта | `<Compile>` link (хак) | `<ProjectReference>` ✅ |
| Лишние csproj-свойства | нет | `AllowUnsafeBlocks`, `Optimize` |
| `typeof(T).Assembly` паттерн | `GetEntryAssembly()!` | `typeof(Program).Assembly` ✅ |

## Ключевые находки

### 1. Скилл НЕ исправил главную ошибку, которую обещал исправить

Скилл прямо предупреждает:
> *"Do NOT manually write a `<PackageReference>` with a version number — BDN versions in training data are outdated and may lack support for current .NET runtimes."*

Оба агента написали `Version="0.14.0"`. Актуальная версия BDN: **0.15.8**.
Разница в 1.5 минорные версии, реальный ущерб минимален — но это именно та ошибка,
которую скилл должен был предотвратить.

### 2. Скилл значительно снизил количество итераций

Messages-токены: 14.6k → 6.8k (**-53%**). Системные токены одинаковые (те же инструменты),
значит агент со скиллом потратил в 2.1x меньше токенов на диалог — меньше правил, меньше итерировал.

### 3. Архитектурное решение лучше со скиллом

Без скилла: хакерский `<Compile Include>` (ссылка на исходник через linked file) + лишний NuGet пакет.  
Со скиллом: нормальный `<ProjectReference>`. Это не связано с BDN-специфичным знанием — 
вероятно эффект от более "уверенного" агента.

### 4. Со скиллом появились ненужные свойства

`<AllowUnsafeBlocks>true</AllowUnsafeBlocks>` и `<Optimize>true</Optimize>` — ни то, ни другое
не нужно для BDN-проекта. Первое избыточно, второе противоречит самому скиллу
(который советует запускать через `-c Release`, где Optimize уже включён).

## Вывод

Скилл помог с *процессом* (меньше итераций, лучше структура проекта), но не с
*конкретной ошибкой*, которую он обещал предотвратить. Это само по себе интересная
находка для критической статьи: скилл улучшает работу агента в целом,
но не обязательно в том направлении, которое задекларировано.
